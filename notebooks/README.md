# Source normalization

Run notebooks in order, using **Restart Kernel and Run All**. They work from the repository root or this directory. Install `requirements.txt` in the selected Python environment first.

- `01_normalize_license_addresses.ipynb` reads the license workbook and writes `processed_data/licenses/`.
- `02_normalize_cad_log.ipynb` reads the full CAD workbook and writes `processed_data/cad/`.
- `03_rental_calls_by_occupancy.ipynb` matches license APNs to the parcel digest, compares CAD addresses and coordinate parcels, and writes overall/category plots and match audits to `occupancy_plots/`. Single-license plots use individual occupancy limits; all-license plots use summed capacity per parcel.
- `04_rental_occupancy_commercial_excluded.ipynb` creates an additional version in `occupancy_plots_commercial_excluded/`, applying all saved PIN exclusions in `excluded_properties.csv` to both call counts and property denominators.
- `05_rental_touching_neighbor_calls.ipynb` uses backend bedroom/building evidence and direct parcel-boundary links to plot selected rental-plus-neighbor calls divided by neighborhood parcel count. Writes `neighborhood_occupancy_plots/`. It runs offline against the exported backend snapshot by default. Unknown building configurations remain excluded and audited.
- `06_direct_listing_calls_and_amenities.ipynb` uses the entire available January 1, 2024-October 16, 2026 span by combining the earlier raw CAD with the later published retained-call extract. It compares direct calls against the residential reference at a 59% booking-occupancy scenario and outputs `direct_listing_calls/`. Source/category completeness differs by window. Parking uses its entire supported January 1-September 20, 2024 window with starred date/settings footnotes; the default parking graph includes all matched parcels, even when the main cohort is above-average only. Network source scanning is optional after saving the inventory. Historical notebooks 03-05 retain their explicitly labeled original source periods.

For new analysis, use the entire available period by default. Preserve and disclose category-specific coverage exceptions rather than silently dropping dates or treating missing coverage as zero. `processing/entire_call_period.py` saves the combined call audit and coverage/source hashes in `processed_data/full_period_calls/`.

The direct report now also has live controls for every licensed address versus current-license addresses with matched Airbnb details, advertised/approved capacity and advertised/licensed bedrooms, over-limit screening and amenity checkboxes. `processing/direct_report_controls.py` builds the complete address audit and deduplicated parcel payload. Recorded approved occupancy is authoritative; no universal bedrooms-to-guests formula is substituted. Multiple license capacities/bedrooms are summed for parcel graphs, while the table retains individual license values. Live SVG and CSV downloads reflect the current controls. Uncovered/excluded license addresses have unavailable call rates and never become zero-call graph observations.

`processing/build_capacity_pages.py` creates `direct_listing_calls/at_or_above_approved.html` (advertised >= approved) and `direct_listing_calls/above_approved.html` (advertised > approved). Both keep their page rule active through filters, resets, exports and the parking fallback. They default to exact groups by advertised guests minus matched approved capacity. Odd advertised capacities are retained and flagged, not rounded or treated as overages solely because they are odd. The normal notebook 06 rebuild also refreshes both pages and their qualifying-listing CSV snapshots.

All three direct-call pages split graph lines by the workbook's permit category: Type 1 owner-occupied, Type 2 non-owner-occupied, and mixed/unknown where applicable. The permit-type selector restricts plots, address rows and downloads, including the parking fallback. A parcel with both categories is classified separately as mixed, not counted in both pure groups. Capacity-page CSVs retain the matched certificate types and the parcel comparison group.

Plot images are now individual files in `plots/`, not embedded in web pages or notebooks. Only citizen-initiated calls are analyzed; patrol, crime-hot-spot, traffic/subject-stop, park/walk/talk and community-engagement dispatch labels are excluded even when tagged citizen-initiated. Raw logs/audits remain intact. Run `python -m processing.collect_plots` to refresh the base collection. Guest and count axes use integers, and approved capacity ticks are even numbers.

`07_trend_and_amenity_review.ipynb` reads or rebuilds separate `plots_with_trends/` and `plots_with_trends_with_averages/` folders. It includes support-screened exact-size trend rankings, size-adjusted amenity associations and highest-call review priorities with listing URLs. Overlapping minimum-cutoff curves are not ranked as independent observations. The average-line folder uses unique-parcel series means and compatible residential references, keeping shorter parking coverage explicit. See each generated README for the full interpretation and limitations.

`top_correlations/index.html` is a local interactive explorer for the top ten distinct supported upward associations. That directory contains ten plot PNG/SVG/group-CSV sets. Selecting a factor shows its exact property cohort, including zeros, with searchable size filters, Airbnb evidence and category call records. `python -m processing.top_correlations` rebuilds the package from the ranked trend results and verified citizen-only call records. Trend analysis also refreshes this package automatically. Rankings are exploratory size associations, not causal factors or Pearson-correlation rankings.

`amenity_votes/index.html` is the live amenity/call voting explorer. It includes direct, touching-neighbor and combined scopes, raw/annualized scores, optional subtraction of expected residential-average calls, per-advertiser normalization and optional signed +1/0/-1 votes. Neighbor exposure remains calendar-year; booking adjustment applies only to the focal rental. All raw vote memberships, neighbor links, property/listing scores and a grouped held-out comparison of capacity/amenity models are auditable CSVs. Rebuild with `python -m processing.amenity_votes`. Model-comparison results describe the full saved cohort and do not refit to arbitrary live checkbox combinations.

For notebook 05, `python -m processing.prepare_neighborhoods` rebuilds boundary candidates. `python -m processing.fetch_neighborhood_backend` refreshes the read-only backend export over SSH with external credentials and verified host keys; no credentials are stored in this repository. The SSH key can be specified using `REGISTVR_SSH_KEY`. Run notebook 03 first to refresh the complete CAD coordinate-match audit if the CAD log or parcel digest changes.

Raw inputs are never overwritten. Each executed notebook includes source hashes, row counts, review totals and validation checks. Shared formatting code lives in `processing/`. These are conservative USPS-style text formatting steps, not USPS delivery validation.

CAD exports retain all source rows, including repeated call numbers. `cad_normalized.csv` is the full output; `cad_unique_addresses.csv` is the address audit with source-row frequencies. `cad_address_review.csv` lists unresolved unique addresses; `cad_record_review.csv` also includes invalid/missing coordinates, timestamps or call identifiers. `cad_duplicate_records.csv` identifies repeated call numbers and exact repeated source rows without removing them. Street candidate keys omit missing locality and require geographic checks before joining. Intersections, ranges and other ambiguous locations have blank candidate keys.

These intermediate files are not included in the site's download links. Parcel and CAD matching have not yet been performed by these notebooks.

Before rebuilding listing analyses, run `python -m processing.validate_listing_matches` to audit source-text permits, geometry contradictions and source folder names, then `python -m processing.apply_listing_match_audit` to install verified joins. The original input listing join table and every folder rename are preserved under `processed_data/listing_matches/`. Never use an inferred filename permit as address/license evidence.

`python -m processing.party_combination_analysis` screens same-listing single amenities, amenity pairs, and advertised-capacity combinations against citizen noise/loud-party/disturbance counts. It deduplicates identical exposure groups, applies minimum parcel/event/spatial-cluster support, controls guest capacity/type/license count, and corrects the fitted search for false discoveries. Results, ten exploratory candidate plots, source-property URLs and copied top-ten size trends are in `party_combination_analysis/`. A higher joint association is not automatically synergy or causation; pair-interaction support is audited separately. This small dataset runs on the CPU without CUDA.
